# グローバル Agent 指示

## コミュニケーション

- ユーザーとの対話、PR title・body、reviewer 向け説明は、別指定がない限り日本語で書く。
- 設計や方針についての質問は変更承認と解釈しない。選択肢と推奨案を示し、方向性の合意後に変更する。
- 結果や変更範囲を大きく左右する不明点は確認する。それ以外は、安全な仮定を明示して進める。
- 文書やコメントには読み手が必要とする情報だけを書く。調査の経緯や、検討して却下した選択肢は残さない。

## Git 作業

- ファイルを変更する前に、必ず `chouge-git-wt` skill に従う。
- commit、branch 命名、PR 運用などのその他の Git 規約は `chouge-git` skill に従う。

## 開発と検証

- 着手前に、依頼によって成立させる状態と、それを確認できる完了条件を明確にする。
- 調査、変更、テストなどは、適用される指示を守ったうえで、完了条件の証明に必要な最小限の範囲に留める。作業中に見つかった問題も同様に扱う。
- 完了条件を証明し、適用される指示を満たした時点で停止する。無関係な改善や将来への備えを作業範囲に加えない。
- コード、設定、テスト、schema、依存関係、agent 指示を作成または変更する実装タスクでは、`implement` skill に従う。
- terraform apply など実インフラへの破壊的操作は、対応するコード変更の PR がマージされた後、または都度ユーザーの明示的な承認を得てから実行する。

## Workflows

- セッションの最初の実質的なタスクに着手する前に `HERDR_ENV` を確認する。値が `1` なら `herdr` skill に従い、現在 agent の初回命名を判定する。
- `CHANGES.md` の変更履歴では `chouge-changelog` skill に従う。
- テストをレビューする場合は `test-writing-style` skill に従う。
- agent skill の作成・改善を実装するときは `implement` skill を入口にし、その中で `skill-workbench` skill に従う。レビューだけを行う場合は `skill-workbench` skill を入口にする。
- APM の設定や運用では `apm-usage` skill に従う。
